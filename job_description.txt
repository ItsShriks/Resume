About the job
About usWe build package management for the Conda ecosystem. Our open source tools (Pixi, rattler, rattler-build) are written in Rust and used by hundreds of thousands of developers. You'll find them in finance, at CERN, at biotech companies, and more and more in robotics. We also maintain RoboStack, which packages ROS for Conda so it runs on any OS from a single lockfile.The engineering team is spread across Europe (Netherlands, Germany, UK, Moldova). This new project is based in Berlin, and so is this role.The projectWe're starting a new product: fleet management for robots, built on Pixi. If every robot in a fleet runs a Pixi environment, deploying, updating and rolling back software across the fleet gets a lot easier. You describe what the fleet should run, and the robots get there, whether they sit in one lab or across several sites with bad connectivity.The robot-side agent and the coordination layer are written in Rust. Our goal is that robots, edge nodes and operators talk to each other peer to peer, so things keep working without a central server or a stable internet connection. Pixi handles environments, artifact distribution and atomic updates on the device. Operators use a web frontend (Next.js or Svelte) to see the fleet, follow deployments, read logs and control rollouts.The project is partially funded through Berlin's Pro FIT programme, meaning the role is on-site in our Berlin office.What you'll work on
The on-robot agent in Rust: reconciling environments, reporting health, orchestrating updates
The networking layer: peer discovery, sharing fleet state, distributing packages between robots
The operator web UI and its connection to the Rust backend
Testing on real hardware. We have robots in the office and partners running ROS 2 in the field
Upstream changes to Pixi, rattler and RoboStack when the fleet work needs them
Talking to users, writing docs, and helping decide what the product becomes

What we're looking forYou don't need years of experience. You do need solid fundamentals and the ability to pick things up quickly.
Rust, or a strong background in C++ or Go and the wish to switch. Async Rust (tokio) helps
Some frontend work with React/Next.js, Svelte or Vue. You don't have to be a designer, but you should care whether the UI is pleasant to use
Some robotics background: ROS or ROS 2, a university project, a hobby robot, or a job at a robotics company
Comfort with Linux, basic networking and the command line
You like owning things end to end in a small team
You live in Berlin or are willing to move here

It's a plus if you know distributed systems or P2P (gossip protocols, CRDTs, content-addressed storage), have used conda or Pixi, have shipped software to devices in the field, or have contributed to open source. None of this is required.What we offerYou'll build a new product from the start, together with the people who created Mamba, Pixi, rattler and RoboStack. A lot of your work will be open source and public. We pay a competitive Berlin salary, with 30 days of vacation, the hardware you want, a conference budget, and time for upstream open source work. We help with relocation within the EU.

  Every CV bullet is ONE line (two at most) shaped like:
      <Action verb> <what> [with <tools>] [to / for <why or for whom>], <result>.
  - Start with a strong past-tense action verb (Built, Designed, Integrated, Cut,
    Led, Automated ...); "Designing / Developing" only for ongoing work.
    Never start with a noun ("LiDAR integration ...", "Person-following ...").
  - End with the RESULT: a number from refs/ if one exists (95%, 0.01 cm, 2 of 7

    purpose instead (what it enabled, who used it, what it replaced).
    NEVER invent a number, percentage or outcome to complete the pattern.
  - Context = the situation or reason in a few words ("so the robot can grasp
    while driving", "for offline use on low-end PCs"). Skip it if the line gets long.
  - Weave in the job ad's keywords where they truthfully fit.
  - Full STAR stories (Situation, Task, Action, Result) belong in the cover letter
    and interviews, not in CV bullets. If an entry in refs/ has a "STAR:" block,
    use it for the cover letter.
